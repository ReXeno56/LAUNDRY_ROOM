# 西16设备状态与预约联合查询

预约来源为公开只读的 [X16洗衣机预约文档](https://docs.qq.com/sheet/DT1FqTlV4SWVqWWhs?tab=ss_9ipbgd)。本程序读取预约，不在文档内创建或修改记录。

## 可用性判断

文档分别覆盖一至四号洗衣机和烘干机。设备编号映射集中在 `config.json` 的 `reservations`，使用真实设备ID，不按显示名称猜测。

只有设备采集正常、设备空闲、预约表已核对且当前没有有效预约，才计入“当前可用”。设备空闲但处于预约时段显示“已预约”；预约表不能读取、设备映射不明或设备数据过期时，不把设备称为可直接使用，并显示待确认状态。存在待确认设备时，概览使用“已确认可用”。西21没有配置预约表，继续按设备状态查询。

预约按上海时间展示，使用 `[开始时间, 结束时间)` 判断占用。结束时间等于开始时间加预计使用分钟数；依文档规则过滤缺少必填项、非正数或超过70分钟的无效记录。同台机器重叠或相邻的时段合并，展示当前预约和下一场预约。下一场尚未开始时可以显示“当前可用”，同时提示可用至何时，用户需自行预留完整使用时间。

## 读取与缓存

`laundry/reservation_source.py` 从腾讯文档公开的只读数据端点读取，当前不需要登录、Cookie或腾讯账号配置。它按文档字段类型识别日期、预计使用时间、单选机器和必填项，并完整读取全部记录；不只截取最近一页。分页和读取前后版本一致性验证失败时，不返回假空列表。

初次或文档版本变化时全量读取，未变化时复用已脱敏的时段。读取预算8秒、分页最多3个并发；设备采集与预约读取并行，接口总体等待预算12秒。SQLite `reservation_cache` 与海尔设备缓存分开，保存30秒有效快照并合并多worker的重复查询；失败退避30秒。

预约填写后可能需要下一轮刷新才能反映，页面分别显示设备与预约的采集时间。腾讯文档公开页面的数据协议可能变化；格式不再匹配时会显示预约待确认，需要更新源解析。缓存与公开接口只保存/提供机器、时段和状态，不存储或展示预约人的姓名、寝室和账户信息。

## 两端和接口

- `/api/devices` 保留原有设备字段和 `state`，增加顶层 `reservations` 及设备的 `availability`、`availableNow`、`reservation`。物理空闲与联合可用性分开。
- 网页西16概览、排序及“仅看可用”使用联合状态，卡片展示当前与下一场预约；来源链接打开原文档。
- 小程序使用同一规则，点击“复制预约文档链接”后可在微信打开。新增代码仍需通过开发者工具上传发布。
- 微信结束提醒仍按正在运行的设备及真实结束时间创建。App工程和已有native页面操作保持原行为。

## 验证

本轮共119项测试通过：67项Python、52项Node。包含源读取完整性/版本变化/隐私字段移除、时间边界/跨午夜/重叠合并、五台设备映射、缓存竞争和失败、两端计数/筛选/排序/编辑状态保留及旧响应兼容。

服务器更新前需备份代码、配置及SQLite一致快照。在临时数据库验证新表初始化和完整测试后更新Web服务；提醒进程无功能变化，无需中断正在进行的派发。
